## 2. 코드·보안

| 등급 | 지적 | 조치 |
|---|---|---|
| 🔴 1 | 사진 경로: 메시지 속 첫 주소를 발신자로 씀. 그래서 「seojun… 확인해 주세요, 저는 attacker@…」 같은 메시지를 보내면 남의 결제 금액·시각·카드 끝자리가 답장 초안과 비교표에 나옴(재현 확인) | `proof.sender_from`을 바꿈: 고객 주소가 하나일 때만 그 주소를 씀. 여러 개면 아무 기록도 읽지 않고 「고객 주소를 넣어 주세요」 안내. 회귀 테스트 추가 |
| 🔴 2 | 모델이 없는 경로(키 없음, 실시간 실행 한도 초과, 호출 실패, /api/evidence)에서는 여전히 첫 주소를 씀 | 주소가 여러 개면 읽지 않도록 함. 측정용 규칙 기준선(옛 정규식)은 `first_address_rule=True`로만 남김. 고친 뒤 다시 돌려 기준선 수치가 같은 것을 확인(38/40, 16/22·21/22, 6/8·6/8, 10/12·11/12) |
| 🟡 | X-Forwarded-For 첫 항목을 써서 IP별 한도를 우회할 수 있음 | Cloud Run이 덧붙이는 마지막 항목을 쓰도록 바꿈 |
| 🟡 | 50MP 넘는 이미지를 디코딩 전에 막지 못함 | `prepare_image`가 디코딩 전에 크기를 확인함 |
| 🟡 | 메시지가 「발신자는 …」이라고 써서 읽는 쪽을 유도할 수 있음. 주소가 하나면 그 주소를 믿음 | README 한계에 적음: 판매자는 실제 메일 발신자와 같은지 확인할 것. 화면에는 항상 어느 주소를 썼는지 보임 |
| 🟡 | 공개 전 내부 문서(HANDOFF.md, docs/win_gate*, docs/open-agent-2026-10-25/HANDOVER.md, 로컬 경로) | 대표 결정 사항으로 남김(§5). 비밀번호·키 같은 비밀값은 없음 |
| ✅ | 테스트 59개 통과(유료 호출 없음) · 작업 트리와 git 전체 기록에 키·토큰 없음 · .env.local은 git 제외 · 공개 모드: 키가 브라우저로 가지 않음, API 문서 꺼짐, 스택 트레이스 노출 없음, 업로드 형식·크기 제한, 방문자별 데이터 분리 | 확인됨 |

추가로 찾아 고친 것(녹화 중 직접 발견):
- 답장에 「CUSTOMER님」처럼 가림 표시가 한글에 붙은 채 나간 문제. 검사식이 `\b` 경계에 걸려 못 잡았음 → 정규식과 테스트를 고침.
- 사진의 상태를 읽지 못한 경우 비교표에 「differs」로 나오던 문제 → 「not read / not checkable」로 표시.
